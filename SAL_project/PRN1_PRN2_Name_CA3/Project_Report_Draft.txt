1. ABSTRACT & EXECUTIVE SUMMARY
========================================================================================
In contemporary higher education administration, the processing of continuous assessment
grades remains heavily reliant on manual spreadsheet data entry, ad-hoc formulas, and
individual document editing. This paradigm exposes examination departments to critical
human errors, including transcription mistakes, unnoticed out-of-boundary marks (such as
negative values or scores exceeding 100), absence of audit trails, and extreme time lag in
distributing results to students.

This project introduces a production-ready, fully autonomous software automation engine
engineered in Python 3.13. The solution implements a two-tier defensive exception handling
architecture combining global schema verification with row-isolated boundary checking.
It seamlessly ingests batch student performance records from Microsoft Excel workbooks,
validates data integrity, performs academic grading calculations, synthesizes vectorized,
publication-quality PDF report cards in bulk via ReportLab Platypus, and exports a styled
master summary spreadsheet using OpenPyXL.

Extensive validation over clean and corrupted test datasets confirms that the engine operates
with a zero-crash guarantee, cleanly isolating invalid records into an audit log while
processing valid cohort rows at sub-second execution speeds.

3. PROBLEM STATEMENT, LITERATURE CONTEXT & MOTIVATION
========================================================================================
3.1 The Academic Administrative Bottleneck
During internal assessment cycles (such as CA3), faculty members must compile scores across
multiple subjects (Mathematics, Science, English) and attendance percentages for hundreds
of enrolled students. In traditional institutions, this involves:
1. Downloading raw grade spreadsheets from various course coordinators.
2. Manually calculating totals, percentages, and letter grades using spreadsheet formulas.
3. Performing manual spot-checks to verify if any entered score is erroneous.
4. Exporting or copy-pasting records into word processors to perform mail-merges.
5. Printing or saving individual PDF report cards one by one.

3.2 Identified Deficiencies in Manual Approaches
- Data Corruption Risks: Manual entry often permits erroneous entries such as '-15' (negative mark),
  '150' (score > 100), or 'Absent' (text in numeric field) to silently pass through formulas.
- Lack of Audit Trails: When an error is manually corrected, no structured history or audit log
  explains when, why, or what data was modified.
- High Time Complexity: Processing a batch of 60 students manually takes between 45 and 90 minutes.
- Human Fatigue: Repetitive tasks lead to cognitive fatigue and higher error rates near deadlines.

3.3 Proposed Automated Solution
The Automated Student Marks Processing System solves this bottleneck by providing a deterministic,
reproducible, and completely autonomous pipeline that completes the entire batch ingestion,
validation, grading, and bulk PDF synthesis in less than 0.5 seconds.

5. SYSTEM ARCHITECTURE & END-TO-END EXECUTION PIPELINE
========================================================================================
The software architecture follows a clean 4-stage pipeline design:

[Stage 1: Ingestion & Path Resolution]
- Accepts target Excel file path via CLI argument (e.g., `python main.py custom_sheet.xlsx`)
  or defaults to `student_input_valid.xlsx`.
- Resolves paths dynamically using Python's `pathlib.Path`.

[Stage 2: Tier 1 Exception Guard (File & Schema Integrity)]
- Wraps file access in an outer `try...except (FileNotFoundError, KeyError, Exception)` block.
- Validates that the file exists on disk.
- Ingests the sheet into a Pandas DataFrame using `openpyxl`.
- Verifies that all 6 mandatory columns exist:
  ['Student ID', 'Name', 'Math', 'Science', 'English', 'Attendance %']
- If missing, logs the diagnostic event to `error_log.txt` and terminates gracefully.

[Stage 3: Tier 2 Exception Guard (Row-by-Row Validation Loop)]
- Iterates across rows in an inner `try...except ValueError` block.
- Step 3.1: Validates primary key presence (Student ID & Student Name != Null/Blank).
- Step 3.2: Converts Math, Science, and English to float; catches string/symbol anomalies.
- Step 3.3: Checks academic score bounds: 0.0 <= score <= 100.0.
- Step 3.4: Converts Attendance % to float and checks bounds: 0.0 <= attendance <= 100.0.
- If any check fails, raises `ValueError`, catches it, writes full row context to `error_log.txt`,
  increments `skipped_count`, and continues to the next row without stopping execution.

[Stage 4: Computation, PDF Synthesis & Master Excel Export]
- Computes Total Marks (out of 300), Aggregate Percentage, Academic Grade, and Pass/Fail Status.
- Invokes ReportLab Platypus to construct `Output_PDFs/ReportCard_<StudentID>.pdf`.
- Invokes OpenPyXL to build and format `Processed_Results.xlsx` with navy blue headers,
  centered alignments, cell borders, and auto-fitted column widths.

6. MATHEMATICAL FORMULATIONS & ACADEMIC GRADING ALGORITHMS
========================================================================================
Let M_Math, M_Science, and M_English denote the validated scores awarded to a student,
where each score satisfies the boundary condition: 0.0 <= M_i <= 100.0.

1. Total Marks Computation:
   Total Marks = M_Math + M_Science + M_English   (Maximum: 300.0)

2. Aggregate Percentage Computation:
   Percentage (%) = (Total Marks / 300.0) * 100.0

3. Individual Subject Passing Criterion:
   Pass(M_i) = TRUE if M_i >= 35.0, else FALSE (Minimum 35.0 per subject required).

4. Overall Result Status:
   Result = 'PASS' if (M_Math >= 35.0 AND M_Science >= 35.0 AND M_English >= 35.0 AND Percentage >= 40.0%)
   Result = 'FAIL' otherwise

5. Academic Grade Allocation Schedule:
   +-------------+----------------------+--------------------+---------------------------------------+
   | Grade       | Percentage Threshold | Passing Condition  | Academic Performance Classification   |
   +-------------+----------------------+--------------------+---------------------------------------+
   | Grade A     | Percentage >= 80.0%  | All Subjects >= 35 | First Class with Distinction          |
   | Grade B     | 65.0% <= % < 80.0%   | All Subjects >= 35 | First Class (Promoted)                |
   | Grade C     | 50.0% <= % < 65.0%   | All Subjects >= 35 | Second Class (Promoted)               |
   | Grade Pass  | 40.0% <= % < 50.0%   | All Subjects >= 35 | Pass Class (Promoted)                 |
   | Grade Fail  | Percentage < 40.0%   | Any Subject < 35   | Fail / Re-evaluation Required         |
   +-------------+----------------------+--------------------+---------------------------------------+

7. DEFENSIVE EXCEPTION HANDLING ARCHITECTURE (TWO-TIER DESIGN)
========================================================================================
A critical requirement of this project is production-grade resilience. The system implements
exactly two rigorously separated exception handling tiers:

7.1 Scenario 1: File & Schema Integrity Exception Handling
- Scope: File-system level and tabular schema validation.
- Trapped Exceptions: `FileNotFoundError`, `KeyError`, generic `Exception`.
- Trigger Conditions:
  * User provides a non-existent file path (e.g., `python main.py missing.xlsx`).
  * Workbook is corrupted or missing essential columns (e.g., 'Math' column renamed or deleted).
- Action Taken:
  * Intercepts the exception before the iteration loop starts.
  * Writes a high-priority diagnostic entry to `error_log.txt` with timestamp, requested path,
    and missing schema details.
  * Prints a clear, user-friendly terminal notification and halts execution safely with 0 crash.

7.2 Scenario 2: Row Data Integrity & Boundary Exception Handling
- Scope: Record-level validation inside the iterative batch loop.
- Trapped Exceptions: `ValueError`, `TypeError`.
- Trigger Conditions:
  * Negative score (e.g., Math = -15).
  * Score > 100 (e.g., Science = 150).
  * Non-numeric text value (e.g., English = 'Absent').
  * Missing primary identifier (e.g., Student ID = None or empty string).
- Action Taken:
  * Isolates the specific row immediately upon encountering the invalid field.
  * Formats a detailed diagnostic payload containing Excel row number, Student ID, and row dictionary.
  * Appends the record to `error_log.txt`.
  * Increments `skipped_count`.
  * Executes Python `continue` keyword to advance to the next student record.
  * Valid records in the cohort continue processing and generating PDFs uninterrupted.

8. TECHNICAL IMPLEMENTATION DETAILS & LIBRARY STACK
========================================================================================
The project leverages a modern, robust Python software stack:

- Python 3.13 / 3.x: Core runtime environment providing strong typing, path resolution,
  and native exception handling.
- Pandas (v2.3.3): Industrial-strength tabular data manipulation library used for ingesting
  Excel files, handling NaN checks via `pd.isna()`, and transforming records into DataFrames.
- OpenPyXL (v3.1.5): Low-level Excel workbook manipulation engine used to apply professional
  typography, header fills (`#1A365D`), cell borders, text alignments, and column auto-sizing.
- ReportLab (v5.0.1): High-performance document generation engine. Platypus (`SimpleDocTemplate`,
  `Paragraph`, `Table`, `Spacer`, `HRFlowable`) is used to construct vector PDF report cards
  with zero external rendering dependencies.
- Python-PPTX (v1.0.2): Programmatic presentation generator used to construct the official
  13-slide PowerPoint presentation deck (`Presentation_Slides.pptx`).
