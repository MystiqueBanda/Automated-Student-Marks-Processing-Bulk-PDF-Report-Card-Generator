• Official Artifacts: Print-ready ReportLab vector PDFs and formatted OpenPyXL master summary sheets.

SLIDE 3: PROBLEM STATEMENT: INEFFICIENCIES OF MANUAL GRADING
========================================================================================
[Header] THE PROBLEM IN TRADITIONAL ACADEMIC GRADING

[Left Box: Critical Bottlenecks]
• Manual Spreadsheet Calculation: Faculty manually calculate sums and percentages, leading to
  human arithmetic fatigue and transcription mistakes.
• Undetected Boundary Violations: Spreadsheets silently accept negative marks (e.g. -15), scores
  exceeding 100 (e.g. 150), or string entries (e.g. 'Absent') without raising validation errors.
• Zero Structured Audit Trail: Manual modifications leave no record of why or when records were changed.
• Tedious Report Card Creation: Faculty spend hours doing manual mail-merges in Word processors.

[Right Box: Consequences & Risk]
• Published transcripts contain erroneous marks, compromising academic integrity.
• Administrative delays in releasing results before university deadlines.
• Significant wasted faculty hours that could be dedicated to research and instruction.

SLIDE 6: SYSTEM ARCHITECTURE & EXECUTION FLOWCHART
========================================================================================
[Header] SYSTEM ARCHITECTURE & EXECUTION FLOWCHART

[Visual Component]
• Embedded Full-Width Flowchart Diagram:
  Raw Excel File (.xlsx) -> 1. File Check (Exists + 6 columns)
    - If Missing -> error_log.txt (Log error and stop safely)
    - If OK -> 2. Row Check (Check each student row)
      - If Invalid row -> error_log.txt (Log row and skip student via 'continue')
      - If Valid row -> 3. Math and Grading (Total, percentage, grade)
        -> 4. Output Files (Student PDFs + Processed_Results.xlsx)

[Core Takeaways]
• Phase 1 (Ingestion & File Guard): Outer try-except intercepts missing files & corrupted schemas.
• Phase 2 (Row Validation Loop): Inner try-except enforces [0, 100] bounds; skips dirty rows without crashing.
• Phase 3 (Output Synthesis): Produces bulk ReportLab PDF report cards and master OpenPyXL Excel reports.

SLIDE 8: ACADEMIC COMPUTATION & DYNAMIC GRADING ALGORITHM
========================================================================================
[Header] MATHEMATICAL FORMULATIONS & GRADING LOGIC

[Mathematical Operations]
1. Total Marks Computation:
   Total = Math + Science + English  (Maximum: 300.0)

2. Aggregate Percentage:
   Percentage = (Total / 300.0) * 100.0

3. Subject-Level Pass Condition:
   Pass individual subject if Mark >= 35.0. If any subject < 35.0, overall Result is FAIL.

4. Result Status:
   Result = 'FAIL' if (Any Subject < 35.0 or Percentage < 40.0%); otherwise 'PASS'.

5. Letter Grade Assignment:
   • Grade A: Percentage >= 80.0%
   • Grade B: 65.0% <= Percentage < 80.0%
   • Grade C: 50.0% <= Percentage < 65.0%
   • Grade Pass: 40.0% <= Percentage < 50.0%
   • Grade Fail: Result == FAIL

SLIDE 9: DEFENSIVE EXCEPTION HANDLING: SCENARIO 1 (FILE & SCHEMA)
========================================================================================
[Header] DEFENSIVE EXCEPTION HANDLING: SCENARIO 1 (FILE & SCHEMA)

[Scope & Targets]
• Target Exceptions: FileNotFoundError, KeyError, generic Exception.
• Scope: Outer defensive boundary guarding file access and schema integrity.

[Trigger Conditions]
• User provides an invalid or non-existent file path via command line.
• Excel workbook contains missing or misspelled required column headers.

[Defensive Action & Safety]
• Catches error before any data processing begins.
• Writes structured diagnostic payload to error_log.txt with timestamp and required column list.
• Displays clean terminal warning and halts execution safely with ZERO unhandled crash.

SLIDE 10: DEFENSIVE EXCEPTION HANDLING: SCENARIO 2 (ROW DATA INTEGRITY)
========================================================================================
[Header] DEFENSIVE EXCEPTION HANDLING: SCENARIO 2 (ROW INTEGRITY)

[Scope & Targets]
• Target Exceptions: ValueError, TypeError.
• Scope: Inner defensive boundary wrapping each individual row during iteration.

[Tested Edge Cases]
• Negative Mark: Math = -15 -> Caught by boundary check (score < 0).
• Out-of-Bounds Score: Science = 150 -> Caught by boundary check (score > 100).
• Non-Numeric Entry: English = 'Absent' -> Caught during float(raw_val) conversion.
• Missing Primary Identifier: Student ID is None or blank -> Caught by null check.

[Zero-Crash Guarantee]
• Bad row is isolated immediately; full row data and row number are logged to error_log.txt.
• Executes 'continue' statement to proceed with the next record.
• Valid cohort rows (e.g. STU205) process and generate PDFs without interruption!
